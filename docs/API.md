# DetectAI API Reference

Base URL: `http://localhost:8000/api/v1` (configurable — see `.env.example`).
Interactive docs (Swagger UI) are auto-generated by FastAPI at `/docs` in
non-production environments.

All request/response bodies are JSON. Timestamps are ISO 8601.

## Authentication

Most write endpoints require a bearer token. Read endpoints (`GET`) and
alert ingestion (`POST /alerts`, `POST /webhooks/{id}`) do not — see the
"Auth scope" note at the end of this document for why.

```
POST /auth/register
POST /auth/login
```

`register` always assigns the `viewer` role regardless of what's sent in
the request — see `scripts/create_admin.py` to bootstrap the first admin.

`login` returns `{"access_token": "...", "token_type": "bearer", "role": "..."}`.
Send it as `Authorization: Bearer <token>` on subsequent requests.

Roles: `viewer` (read-only) → `analyst` (+ trigger AI analysis, submit
feedback) → `admin` (+ trigger MITRE sync). Roles are not hierarchical in
code — each protected endpoint lists its own allowed roles explicitly.

## Alerts

```
POST   /alerts                    Ingest an already-normalized alert (CommonAlertSchema body)
GET    /alerts?limit=&offset=      List alerts
GET    /alerts/{alert_id}          Get one alert
POST   /alerts/{alert_id}/analyze  [analyst/admin] Run AI analysis (or return rule-based score if AI_PROVIDER=none)
POST   /alerts/{alert_id}/feedback [analyst/admin] Submit TP/FP/benign/etc. label
GET    /alerts/{alert_id}/feedback Feedback history for an alert
```

`POST /alerts` expects a body matching `CommonAlertSchema`
(`app/schemas/common_alert_schema.py`) — required fields: `timestamp`,
`source`, `source_product`. Every other field is optional and defaults to
`null`/empty, per the "graceful missing data" design (architecture doc §3).

Every ingested alert automatically runs through deduplication,
correlation, and rule-based risk scoring (architecture doc §6) — the
response always includes `risk_score`, `risk_score_breakdown`, and
`investigation_priority`, even with no AI configured.

`feedback` labels must be one of: `true_positive`, `false_positive`,
`benign`, `needs_investigation`, `confirmed_incident`.

## Webhooks

```
POST /webhooks/{connector_id}
```

The real ingestion path for a `GenericWebhookConnector` (see
`connectors/generic.py`). Requires an `X-DetectAI-Signature` header —
HMAC-SHA256 of the raw request body, keyed with the connector's configured
`shared_secret`. Requests with a missing or invalid signature are rejected
with `401` before the body is even parsed as JSON.

## MITRE ATT&CK

```
GET  /mitre/techniques?tactic=&limit=&offset=   List synced techniques, optionally filtered by tactic
GET  /mitre/techniques/{technique_id}            One technique's full detail
POST /mitre/sync                                 [admin] Fetch latest data from MITRE's official STIX bundle
GET  /mitre/alerts/{alert_id}/mapping            Validated, enriched MITRE mapping for one alert
```

`mapping` combines the vendor's own claim (`Alert.existing_mitre_attack_mapping`)
and the most recent valid AI analysis's claim, cross-checked against the
synced reference data. `invalid_technique_ids` in the response lists any
technique ID that doesn't correspond to a real, current ATT&CK technique —
reported, never silently dropped.

## Health

```
GET /health         Liveness — always returns 200 if the process is up
GET /health/ready    Readiness — actually queries the database
```

No `/api/v1` prefix on these — used directly by Docker healthchecks.

## Auth scope (as of Phase 18)

Only the genuinely sensitive write actions (`analyze`, `feedback`
submission, `mitre/sync`) are role-gated. Read endpoints and alert
ingestion (`POST /alerts`, `POST /webhooks/{id}`) are NOT behind user
auth in this MVP — ingestion has its own separate authentication scheme
(webhook HMAC signatures; direct `POST /alerts` is treated as a trusted
internal/connector caller, not analyst traffic). Extending JWT auth to
every endpoint, including reads, is a reasonable next step for a
production deployment but was out of scope here to avoid retrofitting
auth onto every existing test in one pass.
